# 夸克网页登录后保存失败

2026-10-16 收到的构建 10 诊断记录显示：网页登录已提取账号凭证和会话字段，但三次网盘校验均返回 HTTP 401、业务码 31001，提示游客身份。失败发生在保存账号之前，不能据此判定为账号数据库写入失败。

本地使用虚构凭证复现了请求链路中的二次编码：浏览器已有的 `%2F` 被 Ktor Cookie 插件再次编码成 `%252F`。此前仅含普通字母的测试未覆盖这种情况。构建 11 通过 Cookie 存储适配保留浏览器原始值，并保留服务端 Set-Cookie 的编码信息。

另一个问题是刷新会话时，虽然请求显式移除了旧 `__puus`，共享 Cookie 存储仍可能把它带回。登录校验与会话刷新现在使用独立存储；完整凭证被服务器拒绝时，最多尝试一次会话刷新，再用网盘接口严格验证。只有认证验证成功才允许保存，登录尝试也不会改写先前账号。

回归检查使用包含百分号、加号、斜杠和等号的虚构 Cookie，核对实际 HTTP 请求及服务端轮换后的下一次请求；另行检查 401 恢复时不会携带旧会话。iOS 模拟器检查使用生产 Darwin 网络客户端访问本地测试服务，不需要真实账号。原始用户日志和截图不收入仓库。

这些检查覆盖请求传输、会话恢复及诊断导出，真实夸克账号仍需安装新包复测。若仍失败，请开启诊断记录，重现一次后导出 ZIP；构建 11 的校验事件新增重试次数与 Cookie 传输模式，便于区分首次拒绝、刷新失败和再次拒绝。
